# 接受的 Portrait 应用层差异

原生端以退役 WebUI（`c6504af`）为视觉基准，目标是观感与节奏等价，允许像素差异（ADR 0010）。#138 的实机对照和代码核对中，有两项差异由应用代码产生，但现有行为已经提供清楚反馈，首版保留，不要求逐项复刻 WebUI。

## 接受的差异

- **GenUI Halo / Rim 的触发时机与落点**。WebUI 在开始生成时触发，rim 位于进度条；Native 在成功结束后触发，rim 位于阅读区域边缘。Native 用它确认新视图已经生成，而不是把它当作生成进度指示。Reduce Motion 下不播放 Halo / Rim。见 #138。
- **Feynman Thinking / tool 的折叠过渡**。WebUI 的 `<details>` 本身没有过渡；Native 的 `ui.Collapsible` 为高度和箭头提供约 200ms 的过渡，帮助读者理解内容展开或收起的位置。这是 Native 新增的反馈，保留。Reduce Motion 下直接落位。见 #138。

## 什么情况下重新考虑

- 实机验收发现 Halo / Rim 的时机或落点让读者误判生成是否完成，或者折叠过渡让 Thinking / tool 的状态难以理解：重新开 issue，附上具体操作和连续帧。
- 动效出现残影、重叠、裁切、布局跳动或 Reduce Motion 仍播放：按 bug 处理，不属于这里接受的差异。
- 产品目标从观感和节奏等价改为逐项复刻 WebUI：重新评估这两项应用行为；不需要先扩展 MyGo 框架。

不属于这里的：#138 已拆出的六项应用层修复与增强（#144–#149）、Feynman 选择器（#139），以及已有 MyGo 框架缺口（#89、#91–#97）。
