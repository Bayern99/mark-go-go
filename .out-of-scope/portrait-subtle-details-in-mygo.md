# 为细微的 Portrait 质感修改 vendored MyGo

原生端以退役 WebUI（`c6504af`）为视觉基准，目标是观感与节奏等价，允许像素差异（ADR 0010）。WebUI 里有一些效果，MyGo 目前表达不了；把它们补进 vendored 框架，代价远大于用户能看到的差别。下面这几项因此不做，保持现在最接近的做法。

## 不做的效果

- **Preview 正文的字间距**（WebUI 为 `letter-spacing: 0.01em`，16px 下 0.16px）。编辑器自己排版，字间距要进入行布局、光标定位、选区与命中测试，还要保证 UTF-16 偏移和原文字节不变。一行 60 个字约差 10px，中文几乎看不出。见 #89。
- **毛玻璃的 saturate / brightness**（WebUI 为 `blur(14px) saturate(160%) brightness(1.02)` 等）。要给 `glass.Blur` 加字段，并同步 Metal、HLSL、GLSL 着色器和 CPU 实现，在 macOS 与 Windows 上重新生成。差别只在抽屉和浮层盖住彩色内容时背后略灰。见 #91。
- **选中胶囊的中途挤压关键帧**（WebUI 在 36% 处做 scaleX / scaleY 挤压）。要给 `ElementTransition.Match` 加关键帧路径，或者在构建时暴露匹配前后的矩形，属于框架 API 扩展。现在胶囊直线滑动并插值宽度，节奏一致，只少了"甩动"感。见 #93。

## 什么情况下重新考虑

- 上游 MyGo 自己提供了这项能力（例如 `ui.Font` 有字间距、`glass.Blur` 有色调参数、过渡支持关键帧）：直接接入，不算推翻这条决定。
- 实机验收发现某一项不只是质感差别，而是造成了错位、裁切或可读性问题：重新开 issue，按 bug 处理。

不属于这里的：画面出错的动效（例如折叠残影压住后文，#96），以及应用代码就能补上的差距（例如文件树没有选中胶囊，见 #138）。
