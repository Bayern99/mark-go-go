# ADR 0020 · Preview 语义垂直节奏与 GFM 边界内原生表格升级

Status: accepted

> 五行 Space 数量与对比度矩阵的后续扩充见 [ADR 0021](0021-wuxing-16-spaces-and-threshold-plates.md)（拟由 8 境 16 套扩至 16 境 32 套，全部 32 套已按生产公式复算通过表格表头 `Ink/TableHeader` WCAG AA 对比度）。

## Context

Mark Go Go 采用 Portrait 2.0 界面设计语言（[ADR 0012](0012-portrait-2-coss-reference-and-contracts.md)、[ADR 0013](0013-arc-experiment-scenery-page-command-bar.md)、[ADR 0014](0014-wuxing-spaces-per-space-accent-and-dark-mode.md)）与「Preview ⇄ Markdown 共用同一原始缓冲、字节保真、共享 Undo/Redo、完整中文 IME 组字」的编辑架构。

结合对外部原生 Markdown 编辑器 `s1dashu/quiet-md`（MIT）及其对 Craft for macOS 文档排版风格诠释的研究，我们对当前 Mark Go Go 的纸面阅读与编辑体验完成了多轮源码级核查，识别出四类高价值问题：

1. **Preview 缺少语义垂直节奏**：`EditorTokens` 仅有正文字号/行高与块内 padding，段落、松散列表与标题前后全部依赖源码空白行（默认 16/28 行高下均为单一 28 点）；`parser.List.Tight` 未被消费，导致紧凑列表相邻项及嵌套列表的净空隙为 0，与段内折行无法区分；代码块底部 `PaddingBottom: 12` 仅扩展绘制不占布局导致上下纸色留白不对称；分隔线写死阅读行高 28 且不随字号档位缩放；引用竖线声明宽 2 与实际绘制宽 3 存在 1 点偏差。
2. **原生 Markdown 表格停留在单层渲染态**：仅有行底 0.5 点内阴影，缺少发丝网格、外层圆角与清晰表头对比；内边距偏紧且估宽与实际编辑框不一致；GFM 列对齐（`b.Align`）已解析但从未渲染（vendored MyGo `editor.View` 尚未提供行内水平对齐能力）；列宽持久化对全表内容哈希导致修改任意单元格文字重开即丢列宽；每格使用完整 Preview `Document` 存在把 `# x` / `- x` 误解析为块级元素的保真隐患；缺少格间键盘导航与 GFM 结构编辑。
3. **GenUI 失败恢复入口冗余**：无旧视图首次失败时，内容区、底部命令胶囊与详情弹层重复出现 Retry，且未按 `Failure.Kind` 提供对应恢复路径。
4. **可折叠顶级标题静止标记偏重**：展开态的折叠三角常驻左缘。

同时需要明确产品边界，避免在借鉴排版秩序与表格体验时引入与 Mark Go Go 定位冲突的多主题换皮或非 GFM 私有文档模型。

## Decision

### 1. 唯一默认纸面与研究参考边界

- **不做多套文档排版主题切换系统**：保留 Mark Go Go 唯一默认纸面排版与 Portrait 2.0 封闭字号阶梯（不引入飞书、Notion、Obsidian 主题或自定义 CSS 主题加载器）。
- **五行 Space 独占色彩身份**：纸色、布景、强调色、状态色与 16 套人工验算的 WCAG AA 深浅配色继续全部由八个五行 Space 派生，不引入外部品牌色或自动反色算法。
- **克制吸收 Craft 式纸面秩序**：吸收清晰块间距阶梯与标题“前大后小”的章节归属感；明确拒绝 1.5 点虚点分隔线（1× 屏发虚且违背 Portrait 平直 `Hairline = 1` 原则）、拒绝覆盖现有封闭标题字号、拒绝引入画板、数据库块、首页文件夹/抽屉堆叠卡片或自有 DocxXML 格式。
- **灵感参考记录**：Mark Go Go 的纸面排版与表格交互为独立设计。文档垂直节奏与表格交互边界研究参考了 Quiet.md（`s1dashu/quiet-md`，MIT，commit `66ee92a968456e31f2d38e5b1e097edd3f53456d`）及其对 Craft for macOS 风格的诠释；仓库不捆绑任何 Quiet.md 源码、样式表、字形或界面资源，新增 Portrait 变量按 `portrait-derived` 登记。

### 2. Preview 语义垂直节奏机制（严禁隐藏空白源行）

- **保留可编辑的结构空行**：实测 vendored MyGo 编辑器证实，用空替换隐藏空白源行再把间距挂到下一段会导致段尾回车后光标消失（`caretRect` 失败）、`↓` 跳过空行、点击空隙落入下一段正文及复制/VoiceOver 丢换行；将空白源行转为 standIn 块则会在段间多出页边距光标停靠点。因此：
  - 块间**第 1 个结构空行**保持为普通可编辑空行，通过 `LineStyle` 将该行行高压至目标段距 `ParagraphGap`；
  - **第 2 个及以后**连续空行保持完整正文行高 `L`，作者连按回车立即可见；
  - 在源码无空行的块边界（如紧凑列表项间、嵌套列表首项），以及存在结构空行但标题前距超出 `ParagraphGap` 时的差额部分，于**可见行**上挂载显式设定高度（`e.Height(gap)`）的 `Above` Block，且其加入顺序必须早于标题折叠 Block 以防折叠三角上移；
  - 代码块内部、front matter、HTML/math 等叶子/standIn 块内的空行不按块间空行压缩；代码块底部 12 点通过挂在最后一行代码下方的真实 `Below` Block 占据布局。
- **四级节奏与默认 16/28 起始值**（保留适合中英混排的 `1.75×` 行高，所有值随阅读字号 15–18 派生并登记在 `portrait.EditorTokens`）：
  - 段内自动折行 / soft & hard break：`0`
  - 紧凑列表（`List.Tight == true`）相邻项：`6`（嵌套列表首项 `4–6`，不与外层叠加）
  - 段落间、松散列表项间、代码块与表格外沿：`ParagraphGap = round(readingSize × 1.0)`（16pt 下为 `16`，基线距 `44`，与光标高度一致）
  - 标题“前大后小”（文档首块上距归零；相邻块取 `max(prev.after, curr.before)`；标题紧跟标题取 `max(prev.after, curr.before / 2)`）：16pt 下 H1 `36–40 / 12–16`、H2 `28–32 / 8–12`、H3 `24 / 8–12`、H4–H6 `20–24 / 4–8`。
- **纸面构件修正**：分隔线高度改由动态编辑器变量驱动，继续保持居中发丝实线；引用竖线声明宽度与绘制宽度统一为 3 点；行内代码暂不增加需底层补丁的细边/圆角胶囊。

### 3. MyGo 编辑器行内水平对齐与 GFM 边界内原生表格升级

- **MyGo 编辑器行内对齐补丁**：`third_party/mygo/ui/editor` 通过 `Draw(ed.paint)` 自绘且原本不支持文本对齐。在编辑器行布局层补齐左/中/右水平对齐，使每条折行的绘制、光标、点击命中测试、选区高亮与 IME 候选锚点共享同一套 X 偏移计算。
- **表格视觉与度量（P0）**：采用表格四角圆角裁切与左缘和正文齐平（左侧 16 点行手柄槽探入页边距）、内部共享边单次绘制发丝网格、随当前五行 Space 染色的柔和强调表头与表头底分隔线（全量通过 16 套 Space WCAG AA 验算）、横向 8 / 纵向 4 起步内边距与 `tablemetrics` 统一净宽/估高、X 方向横向溢出渐隐遮罩（`IgnoreInput` + `AccessHidden`），清理原生包字面量。
- **列宽持久化**：不再仅按全表内容哈希恢复（修复改字重开即丢列宽的既有缺陷）；改为按文档内表格序号、列数与表头特征匹配并保留旧唯一签名回退，结构编辑时显式迁移列宽数组。
- **格内保真与导航（P1）**：单元格视图改为 inline-only 模式以遵守 GFM 单元格纯行内规范（防止 `# x` / `- x` 被块级误解析）并清理陈旧单元状态；支持已有格间 `Tab / ⇧Tab / ↑ / ↓` 导航（`Tab` 在单元格内不再插入原始制表符）与整行/整列选区；中文 IME 组字进行中时按键优先交给输入法，不在未提交前强切焦点。
- **GFM 结构编辑（P2）**：在共享文档缓冲上以单区间最小字节替换实现插行、插列、删行、删列、列对齐与末格 `Tab` 增行，逐行保留原有 CRLF/LF，同步更新 GFM 对齐分隔行，保证单步 Undo/Redo；配固定行/列手柄槽、悬停 `+` 插入钉与 Portrait 右键菜单。
- **明确不做（GFM 边界外）**：合并单元格（`rowspan/colspan`）、单元格底色、垂直对齐、多表头行、标题列、将列宽写入 Markdown 原文以及 sticky 表头。表格列宽继续留在本地 preferences 旁路。

### 4. 界面状态收口

- **GenUI 失败恢复单一主入口**：无旧视图首次失败时主恢复动作归内容区（局部强调态，不全局修改通用 Alert 样式），有旧视图时归底部命令胶囊；Details 弹层仅展示诊断信息不重复 Retry；按 `Failure.Kind` 分派缺 Agent、模型无效、认证失败与临时错误恢复路径（空 `Kind` 安全回退），保留现有 Toast 与 Esc 焦点恢复。
- **可折叠顶级标题静默三角**：折叠态常驻；展开态仅在悬停/按下页边距命中区、`FocusVisible`、无 hover 设备或光标落在该标题行时绘制三角，不改变原按钮、热区、快捷键、Tab 顺序与标题布局。

## Consequences

- `internal/portrait` 新增的垂直节奏与表格设计变量均须满足 ADR 0012 五类契约（来源登记 `portrait-derived`、取值锁定、16 套配色 WCAG AA、封闭阶梯、派生不变量），且原生包字面量只减不增。
- `third_party/mygo/ui/editor` 的行内对齐改动为受控 vendored 补丁，须附带覆盖单行、多行折行与 CJK 命中测试的独立包测试。
- 实施按 Parent Spec `#211` 下的 7 张垂直切片工单（`#212`–`#218`）在独立工作树推进，统一合入集成开发分支后由 Codex 执行 Standards + Spec 双轴审查。
